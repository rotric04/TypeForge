# 🔒 Security Policy

Thank you for helping improve the security of my projects.

The security, privacy, and reliability of my applications are important priorities. If you believe you have discovered a security vulnerability in any repository maintained by me, including **TypeForge AI**, I encourage you to report it responsibly so it can be investigated and addressed promptly.

---

## 🛡️ Supported Projects & Versions

Security updates are provided only for actively maintained releases.

| Project                     | Supported Version                   | Status          |
| --------------------------- | ----------------------------------- | --------------- |
| TypeForge AI                | Latest production release on `main` | ✅ Supported     |
| Other Active Repositories   | Latest tagged release               | ✅ Supported     |
| Archived or Legacy Projects | Any version                         | ❌ Not Supported |

If a vulnerability affects an unsupported version but can also impact the latest supported release, please report it.

---

## 🚨 Reporting a Vulnerability

Please **do not disclose security vulnerabilities publicly** through GitHub Issues, Discussions, social media, or other public channels.

Instead, report them privately via email:

📧 **[mohitassudani.3@gmail.com](mailto:mohitassudani.3@gmail.com)**

When submitting a report, please include as much information as possible:

* Affected repository, application, or service
* Description of the vulnerability
* Step-by-step reproduction instructions
* Proof of concept, screenshots, or logs (if applicable)
* Potential impact and severity assessment
* Suggested mitigation or patch (optional)

Providing detailed information helps reduce investigation time and allows fixes to be released more quickly.

---

## ⏱️ Response Timeline

I aim to follow the timeline below for responsible disclosures:

| Stage                     | Target Time                                  |
| ------------------------- | -------------------------------------------- |
| Acknowledgement of Report | Within 48 hours                              |
| Initial Assessment        | Within 5 business days                       |
| Status Updates            | As needed during investigation               |
| Fix or Mitigation Release | Typically within 14 days for verified issues |

Complex vulnerabilities may require additional time depending on severity, infrastructure impact, and testing requirements.

---

## 🤝 Responsible Disclosure Guidelines

To help protect users and project contributors, please:

* Allow reasonable time for investigation and remediation before public disclosure.
* Avoid accessing, modifying, or deleting data that does not belong to you.
* Avoid actions that could impact service availability or user privacy.
* Make a good-faith effort to prevent unnecessary disruption.

Research conducted in accordance with this policy will be treated respectfully and appreciated.

---

## 🏆 Recognition

Responsible security research strengthens open-source software.

If your report leads to a verified security improvement and you would like to be acknowledged, I will gladly credit you in release notes, security advisories, or project documentation after the issue has been resolved.

---

## 🔐 Security Philosophy

I believe security is not a feature added at the end of development—it is a continuous engineering practice.

Across my projects, I strive to implement:

* Secure authentication and authorization mechanisms
* Principle of least privilege
* Environment-based secret management
* Protected API architectures
* Dependency monitoring and updates
* Secure coding practices and code reviews
* Responsible vulnerability remediation
